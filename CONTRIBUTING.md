# Contributing

Eventra is primarily a portfolio project, but constructive issues and proposed contributions are welcome.

## Workflow

1. Open or reference an issue for meaningful changes.
2. Use a short-lived branch such as `feat/reservation-expiry`, `fix/webhook-idempotency` or `docs/payment-flow`.
3. Prefer Conventional Commit prefixes: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `chore`.
4. Open a pull request describing the problem, solution, testing and any architectural/security implications.
5. Changes should pass linting, type checking, tests and build checks before merge.

## Pull requests

A PR should explain what changed and why, link related issues, identify database/API changes, describe testing, and call out security or concurrency implications. Significant architectural decisions should add or update an ADR.

## Documentation

Documentation is part of the implementation. Update requirements, business rules, API contracts, state machines or ADRs when behavior changes.

## Rights

The project is publicly viewable but is not offered under an open-source license. Submitting a contribution does not grant permission to reuse unrelated portions of the project. Contributors must only submit material they have the right to contribute.
